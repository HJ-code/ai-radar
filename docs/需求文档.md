# 需求文档（PRD）— 多源 AI 热点搜集站

> 版本：v0.4 · 日期：2026-08-25 · 状态：已确认（P0–P4 已实现，P5 待做；信息源可靠性收紧、B站实时搜索化、热点流排序/筛选增强已落地）

## 1. 背景与目标

作为一位长期关注 AI 领域的程序员，需要**第一时间获知 AI 领域热点**（例如大模型发布、更新、业界大事），不能依赖人工手动搜索。目标产品自动完成：**发现** 用户关心的关键词相关真实内容、**搜集** 指定范围内的热点，并 **及时通知** 用户。

一句话定位：**一个由 AI 鉴别真伪、可多源可配置、自动通知的 AI 热点雷达。**

## 2. 目标用户

- 主要用户：作者本人（关注 AI 领域的程序员）。
- 关注的内容：AI 大模型发布/更新、AI 业界动态、AI 编程工具、中文 AI 资讯。
- 使用习惯：PC 浏览器为主，也期望手机端可看（响应式）；走到「吃瓜第一线」。

## 3. 核心需求

### 3.1 追踪关键词（First-hand 通知）
- 用户在页面上**手动输入要追踪的关键词**（如 `GPT-6`、`Claude`）。
- 系统定时扫描各数据源（每源间隔独立可配，默认约 5 分钟）。
- 当出现与关键词**真实相关**的内容时（关键：用 **AI 识别假冒/诱导内容**，过滤谣言、戏仿、蹭热度、账号盗用等），**第一时间**向用户发送通知。
- 通知渠道设计为**可插拔**：一期实现「站内推送 + 浏览器 Notification」，二期扩展 Webhook（Server 酱/企业微信/钉钉/Telegram 等）、邮件。

### 3.2 定时热点搜集（Span 观察）
- 用户可定义**监控范围**（如「AI 业界热点」「AI 编程工具」），每个范围绑定一组搜索词。
- 系统周期性（默认每 5 分钟）从各数据源搜集该范围内的热点，经 **AI 三道关**（真伪识别 → 相关度打分 → 中文摘要）后，以**热点视图**展示给用户。

### 3.3 AI 鉴别真伪
- 对每条候选内容，AI 依据以下证据链判断真伪：
  1. 账号可信度（是否官方/知名账号、粉丝数、是否机器人/自动化）；
  2. 内容措辞（是否疑似戏仿、钓鱼、营销、过火标题）；
  3. 与已知事实/已有条目的冲突；
  4. 互动数据是否异常（如互动量与粉丝基数不匹配的暴涨）。
- 判断结果三档：**真实 / 存疑 / 虚假**；存疑与虚假降权或隐藏，并打标记。
- AI 不可用时降级：仅做「相关度（规则级）」收集与展示，标记 `未鉴定`，功能不中断。

### 3.4 多源可配置
- 数据源做成插件式（每个源一个 Provider），可在页面 **启用 / 停用 / 配置间隔 / 编辑参数**。
- 数据源（全部为免费源，不接入付费源）：

| 源 | 接口 | 费用 | 说明 |
|---|---|---|---|
| Hacker News | Algolia Search API | 免费 | 技术圈热点（互动门槛 points≥50） |
| GitHub | Search / Repositories | 免费（可选 Token） | **高星新仓库**（`stars:>500` 可配） |
| Bilibili | 关键词实时搜索 JSON API | 免费 | B 站科技/AI 视频（view≥1万 或 like≥200） |
| 中文 RSS | 7 个官方 feed | 免费 | 量子位、机器之心、IT之家、极客公园、雷锋网、InfoQ 中文、开源中国（**资讯型，免互动门槛，相关度准入**） |
| Reddit / Google News / Hugging Face | 各自公开接口 | 免费 | 可选接入；部分网络不可达时自动降级 |

> 全部为免费源，无需任何 Key 即可运行。交互型源（HN/GitHub/B站/Reddit/HF）带**热点互动门槛**，互动不达标不入热点榜；资讯/论文型源以相关度准入并在卡片标注「资讯」，不伪造热度。

### 3.5 网页端展示
- 响应式 Web 页面（桌面 + 手机均可用）。
- 视觉：**暗色「雷达 / 作战指挥室」风**，与「第一时间抓热点」的定位匹配，避免千篇一律的卡片模板。
- 页面要素：雷达扫描可视化 + 热点落点；热点列表/详情（含 AI 真伪徽章、中文摘要）；追踪关键词与监控范围管理；数据源启停与配置；通知日志。
- **热点流排序/筛选（2026-08-25）**：热点面板上方控制条——**排序**可选 智能热度（默认，热度×时效衰减）/ 最新发布 / 最早发布 / 刚入库 / 最热 / 互动最多 / 最相关，并可切升降序；**筛选**按 来源(多选) / 监控范围 / 真伪状态(多选) / 时间窗(24h·3天·7天) / 类型(资讯·互动) / 相关度阈值 / 热力阈值，另有全文/作者搜索与「清除」。卡片上的来源、范围、关键词标签可点击直接套用筛选；触底分页、顶部「已加载 N · 共 M」在任意排序/筛选组合下保持正确。

### 3.6 Agent Skills（二期）
- 网页版验收通过后，将「追踪关键词 / 发现热点 / 返回结果」封装为 **Agent Skills**，供其他 AI 直接调用本系统能力。

## 4. 非功能需求

| 项 | 要求 |
|---|---|
| 响应式 | 桌面 / 平板 / 手机自适应 |
| 可用性 | AI Key 缺失时系统仍可运行（降级） |
| 费用可控 | 轮询频率、数据源均可调；默认每 5 分钟；免费源优先 |
| 实时性 | 关键词命中到通知目标 ≤ 1 个轮询周期（感知上「第一时间」） |
| 数据 | 本地 SQLite 存储；去重（按源+外部 id） |
| 通知安全 | 浏览器通知需 HTTPS 或 localhost 上下文 |

## 6. 验收标准（网页版）

1. 启动后端 + 前端后，浏览器能打开页面，看到「雷达指挥室」界面。
2. 未配置任何 Key 时：免费源能自动采集数据并展示（降级「未鉴定」状态）。
3. 各免费源自动采集、去重入库，无任何 Key 依赖。
4. 配置 AI 服务后：命中真实相关内容自动出中文摘要与真伪徽章。
5. 新增关键词后，出现真实相关内容能在 1 个轮询周期内收到站内通知 + 浏览器通知。
6. 手机浏览器访问响应式正常。
7. 数据源可在页面启停、改轮询间隔并立即生效。

## 7. 边界与假设

- **默认值**：轮询频率默认 5 分钟（可配）；每源独立。
- **内容范围**：仅限各数据源公开数据。
- **通知强度**：为避免骚扰，同一关键词对「同一 url」只通知一次。
- **AI 可用性**依赖用户提供的服务；不可用时降级为「未鉴定」收集。

## 8. 风险

| 风险 | 应对 |
|---|---|
| DataSource 接口变动/限流 | 采集器加熔断降级、错误不中断整体 |
| AI 误判 | 三档标记 + 「存疑」不删只降权，用户可追溯原文 |
| 免费源 403（如 Reddit/Google News）| 加 User-Agent、可切换 RSS 通道 |
| 浏览器通知在后台不可用 | 一期前台通知 + 站内未读提示；二期加 Service Worker/Webhook |
