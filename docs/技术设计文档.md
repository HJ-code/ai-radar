# 技术设计文档（TDD）— 多源 AI 热点搜集站

> 版本：v0.5（Node.js + Express · 全免费源）· 日期：2026-08-24 · 状态：已实现（P0–P4 + UI v2 + 信息源可靠性收紧）

## 0. 变更说明

1. **后端由 .NET Core 更换为 Node.js 24 + Express 5**（小工具，轻量优先）。
2. 项目结构改为**标准前后端结构**：`server/`（后端）+ `client/`（前端）。
3. 原 .NET 脚手架已移除，前端沿用 React + Vite + TS + TailwindCSS（现为 **React 19 + Vite 8**）。
4. **数据源调整为全免费**：移除付费的 Twitter/twitterapi.io，新增 Hugging Face；存储改用 Node 内置 `node:sqlite`（零原生依赖）。
5. **后续演进（2026-08-22）**：新增 `settings` KV 表支持 **AI 运行时开关**（DB 持久 > `.env` `AI_ENABLED`）；前端 UI 布局定稿（底部 TICKER 固定视口底、右栏三板块平铺驱动页面、左热点流与通知日志内部滚动）；术语 **「告警关键词」更名「追踪关键词」**。
6. **信息源可靠性收紧（2026-08-24）**：GitHub 采集加 `minStars`（默认 **500**）并丢弃无简介仓库；新增 **B 站科技分区榜**采集器（公开 API、浏览器 UA）；`Collector` 新增 `wholeList`（RSS/B 站每轮只拉一次）；入库前**全局关键词/范围预过滤**；中文官方源扩至 **7 个 RSS feed**（量子位、机器之心 + IT 之家、极客公园、雷锋网、InfoQ 中文、开源中国）；**热点准入互动门槛**（HN≥50 分 / GitHub≥500 星 / B 站 view≥1万 或 like≥200，`extraJson` 可调，资讯型豁免）；AI 相关度重定义（仅主体相关给高分）+ 放宽 doubtful（可信即 real）；**移除 arXiv 源**（无法判热度）；前端数据源面板可编辑配置、热点卡片资讯标签。

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **Node.js 24 + Express 5 + TypeScript** | 轻量、生态成熟；运行用 `tsx`，零编译负担 |
| 前端 | **React 19 + Vite 8 + TypeScript + TailwindCSS v4 + framer-motion** | 响应式 SPA |
| 存储 | **SQLite（Node 内置 `node:sqlite`）**（轻量仓库层，不引 ORM） | 零原生依赖、零编译负担 |
| 调度 | **进程内定时器服务**（每 20s 检查到期源） | 无需额外依赖，源级间隔可配 |
| HTTP | Node 原生 `fetch`（Node 24 内置） | 采集器直接用，无第三方依赖 |
| AI 服务 | **可插拔 `IIntelligenceClient`**（默认 OpenAI 兼容 HTTP） | 对接用户提供的任意兼容服务 |
| 实时推送 | **SSE（Server-Sent Events）** | 服务端→浏览器单向推送，无额外依赖 |
| 通知 | **可插拔 `INotifier`** | 一期 inapp+browser，二期 webhook/email |
| 测试 | **vitest + supertest** | 前后端统一测试栈 |

## 4. 数据模型（SQLite，7 张表）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `ranges` | name, queries_csv, enabled | 监控范围 → 一组搜索词 |
| `keywords` | keyword, enabled, trigger_count, last_hotspot_id | 追踪关键词 |
| `sources` | source_key(唯一), api_key, interval_minutes, last_run_at, extra_json | 源配置，可启停 |
| `items` | (source_key, external_id)唯一, title/text/url/author, published_at, query | 归一化去重原始条目 |
| `hotspots` | url唯一, title/text, hot_score, range_name, ai_status, ai_relevance, summary_zh | AI 鉴定后的热点 |
| `alert_logs` | keyword, channel, status, triggered_at | 通知日志 |
| `settings` | key(唯一), value | KV 配置（如 `ai_enabled` AI 运行时开关） |

- 去重键：`items(source_key, external_id)`、`hotspots(url)`。
- `items.ai_status`: `unscored | pending | real | doubtful | fake`。
- 字段命名 snake_case（SQLite），API 输出用 camelCase（JS 习惯）。

## 5. 采集器插件架构

- 每源一个实现文件，实现统一 `Collector` 接口，输出 `ItemDto`；`registry.ts` 按 `sourceKey` 索引。
- 全部为免费源，无需任何 Key；新增源只需实现 `Collector` 并注册到 `registry.ts`。
- 各源适配明细：

| 源 | 端点 | 归一化映射 / 备注 |
|---|---|---|
| Hacker News | `hn.algolia.com/api/v1/search?query=&tags=story` | objectID→externalId, title/url/author/points |
| Reddit | `reddit.com/search.json?q=&sort=new&t=day`（带 UA） | id, title, selftext, permalink, author, created_utc |
| GitHub | `api.github.com/search/repositories`（可选 Token） | id, full_name, html_url, desc, owner, stars；**`stars:>minStars`（默认 500）**，无简介仓库丢弃 |
| RSS | `ExtraJson.feeds`（默认 7 个：量子位、机器之心、IT之家、极客公园、雷锋网、InfoQ 中文、开源中国） | 条目 guid/link, title, desc, pubDate；资讯型源豁免互动门槛 |
| Google News | `news.google.com/rss/search?q=` | RSS item 同上（网络受限时降级） |
| Hugging Face | `huggingface.co/api/models?sort=trendingScore` | 模型 id, modelId, pipeline_tag, downloads, likes（网络受限时降级） |
| Bilibili | `api.bilibili.com/x/web-interface/ranking/v2?rid=188`（科技分区榜） | bvid→externalId, title, desc, owner, stat/view/like；**须浏览器 UA**，无兜底，风控 -352 时返回空 |

- `Collector` 接口含可选 `wholeList`：RSS / B 站为整库型，**每轮只 search 一次**（避免按 30 个关键词重复抓取），入库 `query` 置空避免误标范围。
- `runner.ts` 在入库前做**全局预过滤**：条目标题/正文/URL 命中任一启用关键词/范围词才入库（`filtered` 计数返回）。

## 6. AI 流水线（P2）

- `ai/client.ts` 实现 OpenAI 兼容 `chat/completions`，配置 `baseUrl / apiKey / model`，用 Node 原生 `fetch`。
- 每条新条目依次（失败降级）过三步：
  1. **真伪识别** → `real | doubtful | fake`（证据：账号可信度/是否官方/措辞/互动异常/与已知冲突）。
  2. **相关度打分** 0–100（对照监控范围与关键词）。
  3. **中文摘要** ≤60 字。
- `real 且相关 ≥ 阈值` → 写入 `hotspots`；`hotScore = 相关度 × log(互动)`；存疑/虚假降权或隐藏。
- **热点准入互动门槛**：交互型源需互动量达标才生成热点（HN points≥50 / GitHub stars≥500 / B 站 view≥1万 或 like≥200 / Reddit score≥50 / HF downloads≥1000；`extraJson` 的 `min<字段>` 可覆盖）；未达标仍记录 AI 评分但不进热点。资讯型源（RSS）豁免。
- **相关度口径（2026-08-24 起）**：只有内容**主体**是关于监控关键词/范围才给高分；仅提及或正文主体是别的话题最高 50 分（低于 `minRelevance`，不再成热点）。判定倾向**可信为 true**：官方媒体/知名账号有来源佐证且无矛盾即 `real`，doubtful 仅用于证据不足（避免把真新闻误判为存疑导致不通知/降权）。
- **未配置 AI Key**：跳过三步，标记 `unscored`，仅收集展示；功能不中断。
- 费用控制：仅处理新条目；可加每日调用上限（二期）。

## 7. 通知层（P3，可插拔）

```ts
interface Notifier { readonly channel: string; notify(ctx: AlertContext): Promise<void> }
```
- `inapp`：通知写入 `alert_logs` + 广播到 SSE 连接 → 前端 `EventSource` → 浏览器 `Notification` 弹窗 + 站内角标。
- `webhook / email`：二期实现，registry 注册即插拔。
- 触发条件（需全部满足）：AI 判 `real`；相关度 ≥ 阈值；互动门槛达标；命中启用关键词；**且为本轮新插入的热点**（不回放存量刷屏）；`items.notified` 去重（同一条只通知一次）。

## 8. 调度

- `scheduler.ts`：进程内 `setInterval(20s)` 扫描 `sources`，到期（`now - last_run ≥ interval_minutes`）则交给 `runner.ts`。
- `runner.ts`：逐源顺序执行，尊重速率限制；整库型源（`wholeList`）只 search 一次；入库前做关键词预过滤；单源失败不中断整体；`POST /api/collect/now` 可手动触发。
- 前后端独立管理：`client/` 用 Vite dev（`/api` 代理到后端），生产用 `express.static` 托管 `client/dist`。

## 10. 前端界面方案（P4）

暗色「雷达 / 作战指挥室」：
- 顶部状态栏（ONLINE/采集时钟）、底部 TICKER 行情条、中央雷达扫描圆盘（blip 落点：越新越靠圆心、热度定亮色/大小）。
- 分栏：热点卡片（真伪徽章 真实/存疑/虚假/未鉴定 + 中文摘要 + 原文链接）；数据源启停面板。
- 追踪关键词/监控范围管理（增删改、立即生效）；通知日志；顶栏铃铛通知中心（含浏览器通知授权）；AI 开关与自检入口；底部 TICKER 行情条常驻视口底。
- 响应式：`lg` 双栏，移动端单列。字体：等宽点缀 + 中文无衬线。
